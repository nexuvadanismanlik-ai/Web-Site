# Nexuva OS — Deployment Guide

## Architecture

| Service | Framework | Package | Port |
|---------|-----------|---------|------|
| API | NestJS + Fastify | `@nexuva/api` | `$PORT` (default 4000) |
| Web | Next.js 14 | `@nexuva/web` | `$PORT` (default 3000) |
| Admin | Next.js 14 | `@nexuva/admin` | `$PORT` (default 3001) |

All three services are deployed to **Render** from this monorepo via `render.yaml`.

---

## Prerequisites

- PostgreSQL database (Render Postgres, Supabase, Neon, etc.)
- Cloudflare R2 bucket for file storage
- GitHub repository containing this code

---

## Environment Variables

### API Service (`nexuva-api`)

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | Yes | `postgresql://user:pass@host:5432/db?schema=public` |
| `JWT_ACCESS_SECRET` | Yes | Min 32 chars — auto-generated by Render |
| `JWT_REFRESH_SECRET` | Yes | Min 32 chars — auto-generated by Render |
| `JWT_ACCESS_EXPIRY` | No | Default: `15m` |
| `JWT_REFRESH_EXPIRY` | No | Default: `7d` |
| `CORS_ORIGINS` | Yes | Comma-separated: `https://nexuva.com,https://admin.nexuva.com` |
| `R2_ACCOUNT_ID` | Yes | Cloudflare account ID |
| `R2_ACCESS_KEY_ID` | Yes | R2 API token key ID |
| `R2_SECRET_ACCESS_KEY` | Yes | R2 API token secret |
| `R2_BUCKET_NAME` | No | Default: `nexuva-os` |
| `R2_PUBLIC_URL` | Yes | e.g. `https://pub-xxx.r2.dev` |
| `EMAIL_PROVIDER` | No | Default: `resend` |
| `EMAIL_FROM` | Yes | e.g. `noreply@nexuva.com` |
| `RESEND_API_KEY` | Yes (if using Resend) | Resend API key |

### Web Service (`nexuva-web`)

| Variable | Required | Notes |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | Yes | Full API URL: `https://nexuva-api.onrender.com/api/v1` |

### Admin Service (`nexuva-admin`)

| Variable | Required | Notes |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | Yes | Full API URL: `https://nexuva-api.onrender.com/api/v1` |
| `NEXTAUTH_URL` | Yes | Admin public URL: `https://nexuva-admin.onrender.com` |
| `NEXTAUTH_SECRET` | Yes | Auto-generated by Render |

## Deployment Steps

### 1. GitHub Setup

```bash
# From repo root
git init
git add .
git commit -m "Initial commit: Nexuva OS"
git remote add origin https://github.com/<org>/<repo>.git
git push -u origin main
```

### 2. Database

Create a PostgreSQL database. On Render:
- Dashboard → New → PostgreSQL
- Copy the **Internal Database URL** (for API on Render)
- Or use external: Supabase, Neon, etc.

### 3. Render Setup

**Option A — render.yaml (recommended)**
1. Dashboard → New → Blueprint
2. Connect GitHub repo
3. Render reads `render.yaml` and creates all 3 services automatically
4. Set all `sync: false` environment variables in each service's dashboard

**Option B — Manual**
Create three Web Services with these settings:

**API:**
- Build: `pnpm install && pnpm --filter @nexuva/shared run build && pnpm --filter @nexuva/api run build`
- Start: `pnpm --filter @nexuva/api run start:prod`

**Web:**
- Build: `pnpm install && pnpm --filter @nexuva/shared run build && pnpm --filter @nexuva/web run build`
- Start: `pnpm --filter @nexuva/web run start`

**Admin:**
- Build: `pnpm install && pnpm --filter @nexuva/shared run build && pnpm --filter @nexuva/admin run build`
- Start: `pnpm --filter @nexuva/admin run start`

### 4. Post-Deploy Wiring

After all three services are running, update cross-service env vars:
1. `CORS_ORIGINS` on the API: add the final web + admin URLs
2. `NEXT_PUBLIC_API_URL` on web + admin: set to the API's public URL
3. `NEXTAUTH_URL` on admin: set to admin's public URL
4. Redeploy all three services after updating

## Build Pipeline (What Happens on Render)

```
pnpm install                         # install all workspace deps
pnpm --filter @nexuva/shared build   # compile packages/shared → dist/index.js
                                     # (must run before API build — API requires it at runtime)
pnpm --filter @nexuva/api build      # prisma generate + nest build → apps/api/dist/
```

On first start:
```
prisma migrate deploy                # applies all pending migrations to DATABASE_URL
node dist/main                       # starts the NestJS server
```

## Local Development

```bash
# 1. Install dependencies
pnpm install

# 2. Build shared package (required for NestJS runtime)
pnpm --filter @nexuva/shared build

# 3. Copy and fill environment variables
cp .env.example .env

# 4. Start local PostgreSQL (Docker)
pnpm docker:up

# 5. Run migrations
cd apps/api && pnpm prisma migrate dev --name init

# 6. Start all services in parallel (Turborepo)
pnpm dev
```

## Monorepo Structure

```
nexuva-web/
├── apps/
│   ├── api/          @nexuva/api    — NestJS backend
│   ├── web/          @nexuva/web    — Public Next.js site
│   └── admin/        @nexuva/admin  — Admin Next.js panel
├── packages/
│   ├── shared/       @nexuva/shared — Runtime constants, validators, utils
│   ├── types/        @nexuva/types  — TypeScript type definitions (type-only)
│   └── ui/           @nexuva/ui     — Shared React components
├── tooling/
│   └── typescript/                  — Shared tsconfig bases
├── render.yaml                      — Render deploy config
└── turbo.json                       — Turborepo task graph
```

## Notes

- **`@nexuva/shared`** must be built before the API boots — the NestJS runtime requires compiled JS (TypeScript source is not executable by Node.js). The `start:prod` script handles this via the build order.
- **Migrations** run automatically on each deploy via `prisma migrate deploy` in `start:prod`. This is idempotent — already-applied migrations are skipped.
- **`dist/`** directories are gitignored and built fresh on Render each deploy.
- **Secrets** marked `generateValue: true` in render.yaml are auto-generated by Render on first deploy and remain stable across redeployments.
